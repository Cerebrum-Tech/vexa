- **A bot whose browser tab crashes while it waits in the lobby now fails fast instead of hanging forever (#997).** When the host runs out of memory the kernel kills the meeting tab's renderer; the bot's admission poll used to sit on a read that never returned, the container stayed alive, the meeting stayed `awaiting_admission`, and the user could not request that meeting again. The join layer now races every platform's join and admission drive against the page's `crash` event and reports a transient `join_failure`, so the meeting converges to `failed` and the control plane's retry policy takes over.
